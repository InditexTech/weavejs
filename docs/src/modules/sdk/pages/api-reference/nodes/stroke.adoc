= WeaveStrokeNode
:description: Stroke node API Reference

== Overview

The https://github.com/InditexTech/weavejs/blob/main/code/packages/sdk/src/nodes/stroke/stroke.ts[WeaveStrokeNode]
class represents a multi-point continuous line or path on the Weave.js canvas. It is a versatile and essential node type for
building tools like freehand drawing.

Built on top of Konva’s https://konvajs.org/api/Konva.Shape.html[Shape] class shape under the hood, the WeaveStrokeNode
offers full control over the line’s geometry, style, and behavior—all synchronized in real time across users.

The class extends the xref:sdk:api-reference/nodes/node.adoc[WeaveNode] class

== Type

This node `nodeType` property value is `stroke`.

== Import

[source,shell]
----
import { WeaveStrokeNode } from "@inditextech/weave-sdk";
----

== Instantiation

[source,ts]
----
new WeaveStrokeNode(params?: WeaveStrokeNodeParams);
----

== Parameters

For `WeaveStrokeNodeParams`:

[cols="4*"]
|===
| Property | Type | Required | Description

| mono:[config] | mono:[Partial<WeaveStrokeProperties>] | label:green[Required] | Config parameters for the node.
|===

For `WeaveStrokeProperties`:

[cols="5*"]
|===
| Property | Type | Required | Default | Description

| mono:[splineResolution] | mono:[number] |  | mono:[8] | Minimum number of subdivisions used for a curved span of the smoothed curve. Longer spans are subdivided further, by arc length, so that rendered smoothness does not depend on how far apart the recorded points happen to be.
| mono:[splineTargetEdge] | mono:[number] |  | mono:[1] | Target length, in canvas units, of a single rendered edge. Lower values produce a smoother silhouette at the cost of proportionally more rendered vertices.
| mono:[splineMaxSteps] | mono:[number] |  | mono:[48] | Upper bound on the subdivisions used for one span, so an unusually long span cannot inflate the vertex count without limit.
| mono:[resamplingSpacing] | mono:[number] |  | mono:[2] | Minimum spacing between the control points fed to the spline. Applied after simplification, so it mainly guards against duplicate and near-duplicate samples.
| mono:[isEraser] | mono:[boolean] |  | mono:[false] | Whether the stroke behaves as an eraser.
|===

[NOTE]
====
`splineResolution` and `resamplingSpacing` were previously accepted but
ignored — the renderer used hardcoded values regardless. They now take
effect, so a node that passed non-default values will render differently
than it did before.
====

== Stroke look

A stroke can carry a mono:[look] attribute that says how it is drawn. The look is saved with the stroke, so every viewer and every export draws it the same way. A stroke without a look, or with a look whose mono:[version] is not mono:[1], is drawn exactly as in earlier releases.

[source,ts]
----
type WeaveStrokeLook = {
  version: 1;
  outline: 'legacy' | 'round' | 'freehand';
  curve: 'uniform' | 'centripetal' | 'none';
  pressureInterp: 'catmullRom' | 'linear';
  zoomAware: boolean;
  spacingPx: number;
  edgePx: number;
  caps: 'separate' | 'merged';
  ends?: 'round' | 'flat';
  variance?: number;
  width: {
    min: number;
    max: number;
    gamma: number;
    taperStart: number;
    taperEnd: number;
    easing?: 'linear' | 'easeIn' | 'easeOut' | 'easeInOut';
    nibAngle?: number;
    nibContrast?: number;
  };
};
----

Missing or invalid fields fall back to the legacy values, and numbers are clamped to a safe range.

[cols="1,3"]
|===
| Field | Effect

| mono:[outline] | mono:[legacy] is the offset ribbon of earlier releases. mono:[round] draws the union of the tangent quads between neighbours, merged into one polygon where the path bends only slightly, with a disc at every real bend and at the ends, in one fill. Turns, reversals and ends are round and a translucent colour stays uniform. mono:[freehand] currently draws like mono:[round]; it has no outline of its own yet.
| mono:[curve] | mono:[uniform] is the earlier Catmull-Rom curve. mono:[centripetal] does not overshoot or form cusps when points are unevenly spaced. mono:[none] joins the points with straight edges.
| mono:[pressureInterp] | mono:[linear] never leaves the range of the two neighbouring pressures. mono:[catmullRom] is smooth and clamped to that range.
| mono:[zoomAware] | Spacing and subdivision are in screen pixels, so no facet shows at high zoom. Tapers are measured in screen pixels too.
| mono:[caps] | With the mono:[legacy] outline, mono:[separate] draws the round ends over the fill, as before. mono:[merged] puts them in the same fill, so a translucent colour is not darker at the ends.
| mono:[ends] | Optional, mono:[round] by default. With the mono:[round] outline, mono:[flat] draws no disc at the start and end, so they are cut square; a stroke of a single point, or of a single dash, is still a disc. A viewer from a release that does not know the field draws round ends.
| mono:[variance] | Optional, from `0` (none, the default) to `1`. Varies the width smoothly along the stroke, by up to half of it at `1`. The variation depends only on the id of the stroke and the distance along it, so every viewer, every redraw and every zoom level draws the same widths. The preview shown while a stroke is finished and the saved stroke use the same seed. A viewer from a release that does not know the field draws a constant width.
| mono:[width] | Half-width is the stroke width times a fraction between mono:[min] and mono:[max], following pressure raised to mono:[gamma], narrowing over mono:[taperStart] and mono:[taperEnd] with the shape of mono:[width.easing] (mono:[linear], mono:[easeIn], mono:[easeOut], the default, or mono:[easeInOut]). A stroke shorter than mono:[taperStart] and mono:[taperEnd] together shortens both in proportion, so that it still reaches its full width where they meet; a longer one is drawn over the distances given. The defaults reproduce the earlier width.
|===

=== Nib

A look can give the stroke a flat nib, like a calligraphy or fountain pen, with mono:[width.nibAngle] (in degrees, from `-180` to `180`, `0` by default) and mono:[width.nibContrast] (from `0`, the default, to `1`).

The width at a point follows the angle between the direction of travel and the nib: it is the full width when the stroke goes across the nib and narrows, by up to mono:[nibContrast] of it, as the stroke goes along the nib. At a contrast of `0.7` a stroke along the nib is 30% as wide as one across it.

* The direction of travel is read over a distance of two stroke widths (at least four canvas units) centred on the point, so a jittery path does not make the width jitter.
* It applies to the mono:[legacy] ribbon and to the mono:[round] outline, and multiplies the pressure width and the variance.
* A viewer from a release that does not know the fields draws the width without the nib.

=== Viewer-side preview

[source,ts]
----
const stroke = weave.getNodeHandler<WeaveStrokeNode>('stroke');
stroke.setLookPreview({ version: 1, outline: 'round' });  // draw every stroke with this look
stroke.setLookPreview(null);                              // back to the saved looks
----

The preview only changes how this screen draws. It does not change any saved stroke and other users do not see it.

=== Rendered geometry

[source,ts]
----
const stroke = weave.getNodeHandler<WeaveStrokeNode>('stroke');
const geometry = stroke.getRenderedGeometry(konvaStrokeNode);
// { centerline: WeaveStrokePoint[], halfWidths: number[], ends: 'round' | 'flat' } | null

// the geometry the stroke would have with other points, or another look (null is the legacy ribbon)
stroke.getRenderedGeometry(konvaStrokeNode, { points: otherPoints, look: otherLook });
----

Returns the centerline of a stroke and the half-width at each of its points, as the stroke is drawn now, so a feature that works on the drawn shape does not have to rebuild it from the saved points. It returns mono:[null] when the stroke has no points.

* The geometry follows the look in force: the saved look, or the viewer-side preview when one is on. A stroke with no look gets the legacy ribbon's centerline and widths.
* Coordinates are in the node's own space, like mono:[strokeElements].
* For a look that follows the zoom (mono:[zoomAware]) the centerline depends on the current zoom, so ask for it again after the zoom changes.
* The line reaches the last point of the stroke, whatever the spacing of its points, so the same shape drawn from dense points and from a few ends in the same place.
* The geometry of a stroke is kept while its points, width and look are the same, so asking again, or redrawing, does not build it again.
* mono:[ends] is mono:[flat] only for a mono:[round] or mono:[freehand] outline with mono:[ends] set to mono:[flat]; in every other case the ends are round.

=== Erasures

A stroke can have parts of it erased. The mono:[erasures] property lists, for each stretch of a drag with the xref:sdk:api-reference/actions/stroke-eraser-tool.adoc[stroke eraser] over the stroke, the eraser and the path of its centre. The stroke is not cut: its points, look, box and id stay as they were, and the renderer draws it with the erased areas clipped out.

[source,ts]
----
type WeaveStrokeErasure =
  | { shape: 'circle'; radius: number; points: number[] }
  | { shape: 'square'; axes: [number, number, number, number]; points: number[] };
----

* mono:[points] is the path of the centre of the eraser, as x, y, x, y, ..., in the node's own space, like mono:[strokeElements]. One point is a click.
* A circle is the area within mono:[radius] of the path. A square is the area a square sweeps as its centre follows the path; mono:[axes] are the vectors from its centre to the middle of two neighbouring sides (x and y of one, then x and y of the other), so a square that the rotation or scale of the node has turned into a parallelogram is kept as it was.
* What is left is the stroke as it was drawn, to the edge of the eraser: an arc for a circle, straight sides for a square, the edge of the swept area for a drag. No round or square end is added where the stroke is erased, and nothing outside the area changes. An eraser that does not cover the whole width of a stroke leaves the part it did not cover.
* The erased areas may overlap. It works for strokes with no look, for the mono:[legacy] outline, and for the mono:[round] and mono:[freehand] outlines, with the widths, taper, variance, nib, dash and colour the stroke has.
* An entry that is not well formed (no points, a radius that is not positive, numbers that are not finite) is left out, and the stroke is drawn with the rest. A stroke without erasures, or whose erasures do not reach it, is drawn exactly as before.
* When the stroke is resized, its erasures are scaled with its points: the paths and the axes of a square along each axis, and the radius of a circle by the mean of the two scales.
* A viewer of a release that does not know mono:[erasures] draws the stroke in full, and what was erased stays in the saved data of the stroke.

=== Erase mask

[source,ts]
----
const stroke = weave.getNodeHandler<WeaveStrokeNode>('stroke');
stroke.setEraseMask(konvaStrokeNode, [
  { shape: 'circle', radius: 6, points: [40, 10, 60, 10] },
]);
stroke.setEraseMask(konvaStrokeNode, null);  // draw the stroke as it is saved
stroke.getEraseMask(konvaStrokeNode);        // the current mask, or null
----

Hides part of one stroke on this screen, as erasures that are not saved yet: the same entries as mono:[erasures], applied together with them. The stroke eraser uses it while a drag goes on, so the preview is drawn by the same code as the saved erase.

* The mask only changes how this screen draws. It is not saved, other users do not see it, and it is left out when the node is serialized.
* It does not change the box of the stroke.

=== What is left to see

[source,ts]
----
const stroke = weave.getNodeHandler<WeaveStrokeNode>('stroke');
stroke.getVisibleExtent(konvaStrokeNode);
// { empty: boolean, bounds: { x, y, width, height } | null } | null

// with erasures that are not saved yet, and how closely the width is checked, in the node's units
stroke.getVisibleExtent(konvaStrokeNode, extraErasures, 0.5);
----

Works out which places along the centerline still have some of their width showing once the saved erasures, and the ones given, are out. mono:[bounds] is the box of the centerline that is left, with a step of it on each side (the box of the ink is that with the stroke width added all round), and mono:[empty] is true when nothing shows. It returns mono:[null] when the stroke has no points.

* The line is looked at along its length, no more than twice mono:[resolution] apart, also in a long straight stretch between two points, and across its width at mono:[resolution]; by default half a screen pixel.
* A place is given up only when every sample across its width is inside an erasure, so the box is never smaller than what shows, and a sliver that shows is never taken for nothing.

=== The box of a stroke

The box of a stroke is the box of its points widened by half of mono:[strokeWidth] on every side. That is the most the line is drawn away from them, so the frames of a selection and of a hover, snapping, aligning and fitting to the screen surround a thick line, its round ends included, and the frame of a hover and the frame of a selection are the same.

* mono:[getClientRect] of the node gives it, also to a caller that leaves the stroke of a node out of its box: the mono:[stroke] of this node is its ink, not a border.
* The mono:[width] and mono:[height] of the node are still those of the box of the points, and are saved as they were.
* A line drawn thinner than mono:[strokeWidth], as a pen is at speed, has a little room between it and the frame.
* Once the stroke has erasures the box is that of what is left to see (see above), so the frames, snapping, aligning, fitting and the crop of an export follow what shows, and the area the stroke can be picked in is that box with the stroke width round it. Erasing only the middle of a stroke leaves both as they were. A stroke with nothing left to see keeps the box it had. The box is worked out once and kept until the erasures, the geometry or the zoom change.
