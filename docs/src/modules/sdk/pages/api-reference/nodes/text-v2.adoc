= WeaveTextV2Node
:description: Text node with native on-canvas editing API Reference

== Overview

The https://github.com/InditexTech/weavejs/blob/main/code/packages/sdk/src/nodes/text-v2/text-v2.ts[WeaveTextV2Node]
class represents a text element on the Weave.js canvas, with editing drawn natively on the canvas
instead of a DOM textarea overlay. It is a drop-in replacement for
xref:sdk:api-reference/nodes/text.adoc[WeaveTextNode]; the existing class is unchanged and stays available.

Built on a mono:[Konva.Shape] with its own layout engine, it keeps the editing and idle appearance
identical, and supports opt-in rich text.

The class extends the xref:sdk:api-reference/nodes/node.adoc[WeaveNode] class

== Type

This node `nodeType` property value is `text`, the same as mono:[WeaveTextNode].

[NOTE]
====
Existing documents load and render without migration. Register mono:[WeaveTextV2Node] *instead of*
mono:[WeaveTextNode]: a Weave instance holds one handler per node type, so both cannot be registered
together.
====

== Import

[source,ts]
----
import { WeaveTextV2Node } from "@inditextech/weave-sdk";
----

== Instantiation

[source,ts]
----
const node = new WeaveTextV2Node({
  config: {
    edition: { outline: { color: "#0074ff", width: 1, padding: 0 } },
    sizeWarning: { threshold: 200000 },
  },
});
----

== Differences from WeaveTextNode

* Renders through mono:[WeaveTextV2Shape] (a mono:[Konva.Shape]) with Konva.Text-compatible getters
  (mono:[text()], mono:[fontSize()], mono:[getTextWidth()], ...). The mono:[onEnterTextNodeEditMode]
  and mono:[onExitTextNodeEditMode] event payload `node` is a mono:[WeaveTextV2Shape], not a
  mono:[Konva.Text].
* Editing happens on the canvas: a hidden proxy textarea handles typing, IME and clipboard, and the
  caret and selection are painted on the utility layer, together with an outline of the text box
  (useful with fixed width or height). There is no DOM overlay.
* Entering edit mode on existing text selects all of it (like Figma), so typing replaces it; a newly
  created node starts with the caret.
* Selection supports click, drag, double-click (word), triple-click (paragraph), arrows,
  kbd:[Home]/kbd:[End] and kbd:[Up]/kbd:[Down] on visual lines.
* Undo/redo is local to the edit session (typing, deletion, paste and IME composition each coalesce
  into one step). Leaving edit mode commits a single mono:[updateNode], skipped when the text is
  unchanged. While editing, keydown does not propagate to the page, so app-level undo does not fire;
  `window.weaveTextEditing` holds the editing node id.
* Clipboard is plain text only. Large pastes are laid out in time slices.
* All four layouts (`smart`, `auto-all`, `auto-height`, `fixed`) keep their behavior. Auto-sized
  layouts measure from the engine and no longer depend on the zoom level.
* xref:sdk:api-reference/actions/text-tool.adoc[WeaveTextToolAction] works with it unchanged.

== Content model

Content is stored as `blocks` (paragraphs) of `runs` (`{ t, m }`: text and marks). The `text` prop
stays as a derived mirror. A node without `blocks` is synthesized from `text` on load without
rewriting the document; a whole-text `link` becomes a full-range `link` mark.

Marks are `bold`, `italic`, `underline`, `strike`, `color`, `size` and `family` and `link` (a per-run URL). `size` is a ratio of the node `fontSize`, so resizing the node
or calling mono:[setBaseFontSize] scales every run. Blocks may carry `kind` (`ul` or `ol`), `depth`
and `start` to form lists. Documents without marks and lists are byte-identical to before.

Marks and lists already present in a document always render and are preserved when the text is
edited, whatever `richText.enabled` is, so every client shows the same document.

== Rich text

Rich text is switched on *per node* with the boolean attribute mono:[richText]. Nodes without the
attribute follow mono:[config.richText.enabled] (default `false`), so you can offer a plain and a rich
text tool in the same app (see xref:sdk:api-reference/actions/text-tool.adoc[WeaveTextToolAction]).
Turning it off for a node only removes the commands: marks and lists already in it still render. The toolbar is yours: the node only
exposes commands, a format query and events.

[source,ts]
----
const handler = instance.getNodeHandler<WeaveTextV2Node>("text");

handler.toggleMark(node, "bold");                       // whole text, or the editor selection
handler.applyMark(node, "color", "#ff0000", { start: 0, end: 5 });
handler.applyMark(node, "size", 24);                    // px
handler.toggleList(node, "ul");
handler.indent(node);
handler.setBaseFontSize(node, 32);                      // scales every run
const format = handler.getSelectionFormat(node);
----

* While the node is being edited the commands act on the editor selection (the `range` argument is
ignored) and each one is a single session-undo entry. At a collapsed caret, mark commands set the
marks of the next typed text.
* On a selected node that is not being edited they act on `range` (UTF-16 offsets into `text`,
default: the whole text) and are one mono:[updateNode], so one Weave undo step. This lets an
application edit text from a modal.
* When rich text is off for the node every command returns `false` and does nothing. mono:[isRich(node)]
reports it, so a toolbar can show or hide itself.

[cols="1,3"]
|===
|Method |Description

|mono:[applyMark(node, key, value, range?)]
|Set a mark (`undefined` clears it). `size` is in px and stored as a ratio.

|mono:[toggleMark(node, key, range?)]
|Toggle a boolean mark (`bold`, `italic`, `underline`, `strike`): off when the whole range has it.

|mono:[toggleList(node, kind, range?)]
|Toggle `ul` / `ol` on the blocks of the range.

|mono:[indent(node, range?)] / mono:[outdent(node, range?)]
|Change list depth. Outdent at depth 0 removes the list marker.

|mono:[setRunLink(node, url, range?)] / mono:[removeRunLink(node, range?)]
|Link a range to an absolute http(s) URL (others return `false`), or remove it. Same as
mono:[applyMark] with `link`.

|mono:[setBaseFontSize(node, px)]
|Set the node `fontSize`. Event reason `base-size`.

|mono:[getSelectionFormat(node, range?)]
|Per mark `{ state: 'all' | 'none' | 'some', value? }`, `size` in px, and `list: { kind, depth? }`.
|===

When editing with rich text enabled: kbd:[Ctrl]/kbd:[Cmd] + kbd:[B], kbd:[I], kbd:[U] toggle marks;
kbd:[Enter] continues a list item and exits on an empty one; kbd:[Backspace] at the start of an item
outdents it or removes the marker; kbd:[Tab] / kbd:[Shift]+kbd:[Tab] change the depth. Pasting inserts
plain text with the marks at the caret. With it disabled, kbd:[Enter] in a list item still creates
an item with the same `kind` and `depth`.

Link runs are drawn with `link.defaultColor` and an underline; the hovered run uses `link.hoverColor`
and the cursor becomes a pointer only over the run. kbd:[Ctrl]/kbd:[Cmd] + click opens it, as does a
click on an already-selected node. Only http(s) URLs render and open. A node-level `link` (see
xref:sdk:api-reference/nodes/text.adoc#hyperlinks[Hyperlinks]) takes precedence. Links render
whatever `richText.enabled` is; creating and removing them is a command.

Lists show markers in a gutter (`disc`, `circle`, `square`; `1.`, `a.`, `i.` by depth). Numbering is
continuous across consecutive same-depth items and restarts after a plain paragraph or a shallower
item; `start` sets the first number. Markers are not part of `text`.

Images export with the formatting. Exporting to PDF rasterizes each frame, so it follows the image.
Register every font family you use in runs on the server as well.

== Configuration

Same properties as xref:sdk:api-reference/nodes/text.adoc[WeaveTextNode], except `edition`, plus:

[WARNING]
====
mono:[edition.borderSize] does not exist on mono:[WeaveTextV2Node]: there is no DOM textarea border to
size. Passing it is a type error. Use mono:[edition.outline] instead.
====

[cols="1,1,3"]
|===
|Property |Default |Description

|mono:[edition.outline.enabled]
|`true`
|Draw an outline of the text box while editing.

|mono:[edition.outline.color]
|`#0074ff`
|Outline colour.

|mono:[edition.outline.width]
|`1`
|Outline width in screen pixels (constant across zoom levels).

|mono:[edition.outline.padding]
|`0`
|Gap between the text box and the outline, in screen pixels.

|mono:[richText.enabled]
|`false`
|Default for nodes without a `richText` attribute: formatting commands, shortcuts and list key rules.

|mono:[richText.indentStep]
|`1.5`
|List indent per depth, as a multiple of `fontSize`. The total indent is limited so at least 4 times
`fontSize` stays for text in fixed-width nodes. Must be the same on every client.

|mono:[sizeWarning.threshold]
|`200000`
|Serialized size of `blocks` (characters) above which the mono:[onTextSizeWarning] event is emitted.
Content is never truncated.
|===

== Events

[cols="1,2,3"]
|===
|Event |Payload |Description

|mono:[onEnterTextNodeEditMode]
|`+{ node: WeaveTextV2Shape }+`
|An edit session started.

|mono:[onExitTextNodeEditMode]
|`+{ node: WeaveTextV2Shape }+`
|An edit session ended and its content was committed.

|mono:[onTextSelectionChange]
|`+{ node, start, end, format }+`
|The selection, caret or content changed while editing (throttled).

|mono:[onTextFormatChange]
|`+{ node, format, reason: 'command' | 'undo' | 'redo' | 'base-size' }+`
|A format command, undo, redo or base size change ran.

|mono:[onTextSizeWarning]
|`+{ node: WeaveTextV2Shape, size: number, threshold: number }+`
|The serialized `blocks` grew past `sizeWarning.threshold`. Emitted once per crossing.
|===

== Hyperlinks

Same behavior and methods as xref:sdk:api-reference/nodes/text.adoc#hyperlinks[WeaveTextNode]:
mono:[getLink], mono:[setLink] and mono:[removeLink].

== Exports

mono:[WeaveTextV2Node], mono:[WeaveTextV2Shape], mono:[TextLayoutEngine], mono:[TextEditSession],
mono:[TextEditModel] and the related types. mono:[TextEditSession] works on a mono:[TextEditTarget]
and a mono:[TextEditHost], so other shapes can reuse the layout engine and the editor.

== Server side

Measurement and painting work on the node-canvas backend (`setupCanvasBackend()`) and were also
verified on the skia-canvas backend (`setupSkiaBackend()`). Register fonts in your app; they are not
registered by the SDK.
