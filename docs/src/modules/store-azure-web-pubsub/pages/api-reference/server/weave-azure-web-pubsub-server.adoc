= WeaveAzureWebPubsubServer
:description: API reference for the WeaveAzureWebPubsubServer class

== Overview

The WeaveAzureWebPubsubServer is a server-side class in the Weave.js Azure Web PubSub store
that enables real-time collaboration using Azure Web PubSub as the transport layer. It serves
as a store provider, handling the synchronization of shared document state across all clients
connected to a specific room.

Built on top of Yjs, this class leverages Azure's managed Web PubSub infrastructure to offer scalable,
low-latency communication, with support for CRDT-based document syncing, user presence (awareness),
and optional persistence of shared state.

This class enables seamless collaboration by handling server-side:

* Connection management via WebSocket clients
* Document synchronization using CRDTs (through Yjs)
* Broadcasting updates between users in real time
* Support for awareness events
* Support for persistence of the shared-state

== Parameters

[cols="5*"]
|===
| Property | Type | Required | Default | Description

| mono:[pubsubConfig] | mono:[WeaveAzureWebPubsubConfig] | label:green[Required] |  | An object defining the Azure Web PubSub params: endpoint, custom auth (token flow or key) and hub name. By default we promote the use of DefaultAzureCredential from the @azure/identity dependency.
| mono:[eventsHandlerConfig] | mono:[WebPubSubEventHandlerOptions] |  |  | Azure Web PubSub event handler configuration. Use allowedEndpoints to restrict the CloudEvents origin and accessKey to verify the HMAC-SHA256 signature on every inbound event.
| mono:[persistRoom] | mono:[PersistRoom] |  |  | Weave.js Store to use to handle the real-time communication
| mono:[fetchRoom] | mono:[FetchRoom] |  |  | Child nodes to render
| mono:[initialState] | mono:[initialState] |  | mono:[defaultInitialState] | Array of nodes to register and use by the instance
| mono:[syncHostConfig.heartbeat.sendIntervalMs] | mono:[number] |  | mono:[2500] | Interval to send sync room heartbeat to clients, in miliseconds
| mono:[syncHostConfig.resync.checkIntervalMs] | mono:[number] |  | mono:[5000] | Sync host resync request check interval, used to request a resync event to clients when sync host disconnect / reconnect, in miliseconds
| mono:[syncHostConfig.resync.attemptsLimit] | mono:[number] |  | mono:[12] | Maximum limit of resync attempts
|===

== Webhook authentication

The `eventsHandlerConfig` object accepts two fields that together protect the CloudEvents
endpoint from spoofed requests.

[cols="3*"]
|===
| Field | HTTP response on failure | Purpose

| `allowedEndpoints` | `403 Forbidden` | Restricts incoming POST requests to the Azure Web PubSub service hostname. Requests from any other origin are rejected.
| `accessKey` | `401 Unauthorized` | Verifies the `ce-signature` HMAC-SHA256 header (`sha256=Hex(HMAC-SHA256(accessKey, connectionId))`) on every event. Accepts a single key string or `[primary, secondary]` for zero-downtime key rotation.
|===

[source,ts]
----
new WeaveAzureWebPubsubServer({
  pubSubConfig: {
    endpoint: process.env.WEAVE_AZURE_WEB_PUBSUB_ENDPOINT,
    hubName: process.env.WEAVE_AZURE_WEB_PUBSUB_HUB_NAME,
    auth: { key: process.env.WEAVE_AZURE_WEB_PUBSUB_KEY },
  },
  eventsHandlerConfig: {
    // Reject POSTs from origins other than the configured service endpoint
    allowedEndpoints: [process.env.WEAVE_AZURE_WEB_PUBSUB_ENDPOINT],
    // Verify the HMAC-SHA256 signature on every inbound CloudEvent
    accessKey: process.env.WEAVE_AZURE_WEB_PUBSUB_KEY,
  },
});
----

[quote]
____
*Managed identity / `DefaultAzureCredential`*: when no static access key is available,
omit `accessKey`. A warning is logged on every request. Protect the endpoint at the
network level by restricting ingress to
https://learn.microsoft.com/en-us/azure/azure-web-pubsub/concept-service-internals[Azure Web PubSub IP ranges]
via NSG or firewall rules.
____

== Shared-state initial value

If not defined the `defaultInitialState` is used, which is nothing more than:

[mermaid,format=png,role=zoom-in]
....
flowchart TD;
Stage --> gridLayer;
Stage --> mainLayer;
Stage --> selectionLayer;
Stage --> usersPointersLayer;
Stage --> utilityLayer;
....

A xref:main:build/nodes/stage.adoc[Stage] node with 5 children xref:main:build/nodes/layer.adoc[Layer]
nodes, in the specified order (bottom-to-top):

* *gridLayer*: is the layer used by xref:main:build/plugins/stage-grid.adoc[WeaveStageGridPlugin]
to render the reference grid elements.
* *mainLayer*: is the main layer where all the nodes added by the users live.
* *selectionLayer*: is the layer used by xref:main:build/plugins/nodes-selection.adoc[WeaveNodesSelectionPlugin]
to render the selection overlay elements.
* *usersPointersLayer*: is the layer used by xref:main:build/plugins/users-pointers.adoc[WeaveUsersPointersPlugin]
to render the users pointers overlay elements.
* *utilityLayer*: is a wildcard layer defined that can be used by any plugin.

Check out here the https://github.com/InditexTech/weavejs/blob/main/code/packages/store-azure-web-pubsub/src/server/default-initial-state.ts[code]
hat defines the `defaultInitialState` function.
